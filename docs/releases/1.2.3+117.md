# Temporary photo search from the Unison catalogue

Browse Unison pastels now has a photo search button alongside the text search. On iPhone and Android, Search by camera opens the system rear camera; on Windows, Search by photo opens the existing photo chooser. The captured/selected bytes open the existing Unison matching view, where tapping points ranks the three nearest sticks with swatches, prices and availability and allows adding them to the shopping cart. Returning restores the catalogue and text search.

The photo is used in memory and is not uploaded or added to the reference library. Capture uses a maximum 2000px preview, consistent with the existing matching preview. Camera cancellation makes no changes; capture errors leave the button usable. Duplicate taps and callbacks after leaving the screen are guarded. Native iOS/Windows/Android administrator and account checks apply. Android now uses its native WebView for Dakota price/stock reads and cart transfer, sharing the existing DOM scripts and transfer guards. Unison remains hidden on web as explicitly requested on October 19; the public web app receives the general branch update.

Android JavaScript result handling explicitly unwraps the JSON-quoted String returned by Android WebView; iPhone's direct String result remains unchanged. This prevents Android stock checks and cart preflight from failing to parse the retailer response.

Validation: all 18 focused tests plus two mobile script-result tests pass. Photo flow widget checks cover captured bytes, cancellation, duplicate taps, permission errors and disposal; existing catalogue, matching, stock/price, cart and platform tests cover the remaining Unison behavior. Modified components pass analysis. Physical mobile camera interaction requires device verification after deployment.
